## 0. 结论

1. **画像修正原有两处方向性错误，已修（`94c3233`）**（§2.1、§2.2）：BB 免费过牌 / BB 防守被套成「VPIP 中段」，
   3bet / 4bet 线被套成「PFR 宽度」。两处都让对手范围明显偏离实际，而且 poker_manager 实盘配置
   （`--exploit on` + `--search-force-unanchored on`）每个翻后决策都会走到。现在这两类座位直接不做画像修正。
2. **结构性问题是「混合」而不是「条件化」**（§2.3）：画像分布 `w` 只看全局 VPIP / PFR 和 Chen 序，不看这条线上的具体动作，
   再以 α=0.5 跟 blueprint 范围做凸混合，等于把一半质量换成和行动线无关的分布，越是信息量大的线（3bet、4bet）稀释越重。
3. **推荐方案：blueprint 当先验排序 + 按对手在该局面的实测频率做指数倾斜 + 沿行动线连乘**（§4）。
   这是 Ganzfried & Sandholm 的 DBBR 思路在「单个决策点」上的最小 KL 解，数学上就是把每个决策的
   `σ(a|h)` 换成 `σ(a|h)·e^{θ_a}` 再归一，`θ` 由实测频率解出。它同时解决：画像跟行动线脱节、位置无关、
   Chen 序太粗、150 手硬门、`ranges_opt=None` 时画像失效、断点之后的动作被整段丢掉。
   **前提是倾斜直接做在原始 σ 上**：实测（§4.7）翻前首入节点 92%–95% 的组合不在混合区间，边界以下牌的先后只体现在 1e-4 以下的残余值里，
   倾斜前先加 ε/|A| 的均匀抖动会把它抹平，放宽时多出来的质量就变成均匀撒。
4. **代码可以显著变简单**（§4.5）：对手侧把「前缀 reach + 跳 AllIn + limp 当弃牌前缀 + limp_raisers 删步 + 均匀混合 +
   ExploitShape / width_band / Chen 倾斜 / preflop_entry_kinds」收成一条「每个对手决策 → 参考策略 → 倾斜 → 乘」的流水线；
   hero 侧把只覆盖 limp 的 `hero_limp_coef` 换成通用的「按 hero 当时实际用的决策函数重放」，顺带修掉 PM-17 等其它偏离。
5. **先做评估工具再改算法**（§5）：用 hh 日志里的摊牌牌（只用日志，不用 `/api/hands`）算各方法对亮牌的交叉熵，
   现方法 / 关画像 / 新方法同口径比较。没有这个尺子，§4 的收益无法确认。
   **主指标只用翻前全下的摊牌**：普通摊牌按牌力筛过，会系统性地偏袒「把对手想得强」的方法，不能当相对比较的尺子。

## 2. 发现的问题（按影响排序）

### 2.1 BB 免费过牌、BB 防守被套成「VPIP 中段」 —— bug（`94c3233` 已修）

- `preflop_entry_kinds`（`openpoker_advisor.rs:3754`）把 `"call" | "check"` 都归为 `Passive`，注释明说含 BB option check。[事实]
- `Passive` → `CallBand` = Chen 序 `[ceil(pfr·n), ceil(vpip·n))` 这一段权 1、其余 0.05。[事实]
- 但 Profiler 的 VPIP **不计过牌**（`opponent_profile.rs` `observe_hand`：`Fold | Check => {}`），也不分位置。[事实]

BB 免费过牌的真实范围 ≈ 除了会加注的牌之外的所有牌；BB 面对开池的防守范围也远宽于该玩家的平均 VPIP。
用 VPIP 中段去描述它们，方向是系统性地把 BB 想得太强。

示意（翻牌后 1176 个有效组合，VPIP 25%、PFR 10%，BB 在前缀里没有决策 → 先验均匀）：[计算]

| | CallBand 中段（Chen 前 10%–25%） | 其余（Chen 25% 之后） |
|---|---:|---:|
| 实际（过牌范围 ≈ 去掉 Chen 前 12% 加注牌后均匀） | ≈ 15% | ≈ 85% |
| 现代码（α=0.5） | ≈ 46% | ≈ 47% |

触发条件：`--exploit on` 且 BB 的 PFR 也收敛。poker_manager 的 `unanchored_exploit_live_20261023` 就是这个配置，
加上 `--search-force-unanchored on`，平跟池、BB 防守池的每个翻后搜索都会用到。[事实]

**最小修法**：盲位的 `check` 不进 `Passive`，并且 BB / SB 没有主动入池（只过牌或只补齐 / 防守跟注）时这一座不做画像修正
（`TopK` 用的也是全局 VPIP，对 BB 同样不对）。长远看 §4 的方案按位置 × 局面统计，这个问题自然消失。

### 2.2 3bet / 4bet 线被套成「PFR 宽度」 —— bug（`94c3233` 已修）

`Aggressive` → `RaiseBand` = Chen 序前 `ceil(pfr·n)` 个，不管这次是开池、3bet 还是 4bet。[事实]
PFR 是「翻前加注过的手占比」，基本等于开池率；4bet 范围通常只有它的十分之一左右。

示意（4bet 者，blueprint 4bet 范围 ≈ 30 组合 QQ+/AK，PFR 18%）：[计算]

- 经过 ⑤⑥ 后，这 30 个组合只占 ≈ 44% 的质量；Chen 前 18% 里的其余牌（99–JJ、AQ、AJs、KQ…）占 ≈ 37%，剩下是均匀尾巴。
- 也就是说，求解器认为对手 4bet 后一半以上时间不是 QQ+/AK。对手如果真是「4bet = 坚果」型，这个修正的方向和剥削意图正好相反。

另：`preflop_entry_kinds` 把 `all_in` 一律记 `Aggressive`，短码**跟注全下**也会被套 RaiseBand；
Profiler 同样把 `all_in` 记成加注，短码玩家的 PFR 被抬高。`action_kind`（`:1653`）已经有按合法集区分的写法，这两处没用上。[事实]

### 2.3 画像是「混合」不是「条件化」

`r' = (1−α)·r + α·w` 里 `w` 不依赖这手牌的行动线（只依赖全局 VPIP / PFR 和一个三选一形状）。[事实] 后果：

- **信息量越大的线稀释越重**：开池跟注线 `r` 本来就宽，混进 `w` 变化不大；4bet 线 `r` 很窄，混进 `w` 后被拉宽一大截（§2.2）。
- **双峰**：limp 当弃牌时，平跟者的 `r` = 「该位置开池范围之外的牌」（以垃圾牌为主），`w` = Chen 中段；两者混合得到「一半垃圾 + 一半中段」，
  两者都不像真实平跟范围。[推断]
- **跟 25% 均匀平滑叠加**：先混 25% 均匀再混 50% `w`，blueprint 部分只剩 37.5% 权重。

正确的做法是**把画像当成对每个决策的似然修正**（乘法），让每一步的动作都起作用。§4 就是这个。

### 2.4 最需要画像的地方反而不用

- `apply_exploit_width_prior` 遇到 `ranges_opt=None` 直接返回（`let mut ranges = ranges_opt?`）。[事实] 前缀为空时（满桌 UTG 首动作 limp 且没开 limp 当弃牌），
  blueprint 一点信息都没有，画像是唯一信号，却被跳过。
- 断点那一步和之后的翻前动作全部按「无信息」处理（因子 1）。[事实] 例如短码 open shove → 有人 3bet 隔离 → 原 open 者跟注：
  shove 被跳过（`skip_all_in`）、3bet 者在断点后，进翻牌时两个人都几乎是均匀范围。

### 2.5 hero 范围只修了 limp 一类偏离

hero 范围 = blueprint 沿 hero 走过的线算的 reach（hero 不混均匀）。hero 的翻前动作不来自 blueprint 时，真实手牌在自己范围里的权重可能接近 0。
`hero_limp_coef` 修了 limp 规则这一类；以下几类仍按 blueprint σ 算：[事实]

| 偏离来源 | 位置 | 例子 |
|---|---|---|
| PM-17 4bet 剥削 | `fourbet_adjust` | blueprint 弃牌的牌被改成 4bet，影子照常映射到 raise1pot，hero 范围 = blueprint 4bet 范围 |
| 翻前全下启发式 | `preflop_allin_response` | 按 `allin_range_width` + 胜率跟注 |
| 底池赔率地板 | `fallback_with_floor` / `limp_heuristic:pot_odds_call` | blueprint 弃牌的牌被改成跟注 |
| 抽样修剪 | `prune_for_sampling` | 低于 5% 的弃牌被去掉（影响小） |

强制发牌（`real_hand_forced_deal_design_2026_10_25.md`）解决的是访问量，解决不了「解里的对手以为 hero 范围更强」。
`bp2_115653` 分析 §3.1 已经指出过同一类问题。[事实]

### 2.6 其它不一致

- 对手全下（AllIn tag）被跳过 → 全下者范围 ≈ 均匀；而 hero 自己面对全下时用 `allin_range_width`（按码深的全下宽度表）算胜率。
  同一个人的全下范围，hero 决策和翻后搜索用了两套假设。[事实]
- 画像只有全局 VPIP / PFR，而 `opponent_analysis/spots.py` 已经在算分位置的 `rfi`（raise / limp / fold）、`vs_open`（fold / call / 3bet）、
  `vs_3bet`、`steal_defense`。[事实] Rust 侧没用上这些更细的统计。

## 3. 可选方案调研

| 方案 | 出处 | 思路 | 对我们 |
|---|---|---|---|
| A. 自身策略追踪 + 离树动作映射 | Pluribus（Brown & Sandholm, Science 2019） | 所有人的范围都按 bot 自己的策略算；翻前离树尺寸用伪调和映射到最近尺寸，偏差大（且人少）才在翻前做实时搜索 | 这就是我们的锚定路径。解决不了「对手根本不按均衡打」和「blueprint 没有这个动作（limp）」 |
| B. 嵌套子博弈求解 | Libratus（Brown & Sandholm, NeurIPS 2017 *Safe and Nested Subgame Solving*） | 离树动作加进树，从上一个在树节点的范围重解，新动作的范围由解给出 | 理论上最干净；翻前多人重解要叶子值，代价大；而且给出的仍是「均衡对手会拿什么牌这样打」，对偏离大的人群不准 |
| C. 均衡先验 + 频率约束的最小偏离（DBBR） | Ganzfried & Sandholm, AAMAS 2011 *Game Theory-Based Opponent Modeling in Large Imperfect-Information Games* | 以均衡策略为先验，在「各公共局面的动作频率 = 观测值」约束下找离均衡最近的对手策略 | **推荐**。KL 距离下的解是闭式的指数倾斜，计算量可以忽略；保留 blueprint 对手牌的排序，只调整宽度 |
| D. 贝叶斯后验（对手策略的分布） | Southey et al., UAI 2005 *Bayes' Bluff* | 对对手策略类型做后验，再对手牌做后验 | 需要策略空间参数化 + 大量摊牌，太重 |
| E. 手写人群范围表 | HUD / 人工 | 按位置 × 局面配范围 | `limp_heuristic` 就是这种。可以作 C 的「参考策略」来源（blueprint 没有节点时），但不该作为最终范围 |

## 4. 推荐方案：参考策略 × 频率倾斜 × 连乘

### 4.1 公式

对对手 `s` 的每个翻前决策 `t`（局面 `c_t`，实际动作类 `a_t ∈ {fold, call/limp, raise}`）：

```text
σ_ref(a | h)            参考策略（来源见 4.2），用原始值，只把精确 0 抬到极小正数（如 1e-9），不加均匀抖动
σ_opp(a | h) ∝ σ_ref(a | h) · exp(θ_a)                   ← 最小 KL 投影的闭式解
θ 满足  Σ_h prior_t(h) · σ_opp(a | h) = f_c(a)  对每个 a   ← 2–3 个未知数，迭代比例拟合几轮收敛
range_s(h) ∝ Π_t σ_opp(a_t | h)
range_s ← (1−λ)·range_s + λ·g                            ← 倾斜和连乘都做完后再兜底，g 见下
```

- `prior_t` = 该座在第 t 步之前的范围（同一遍连乘里顺手得到）。
- `f_c(a)` = 对手在局面类 `c` 下动作 `a` 的频率，带收缩：`f_c = (n_c·f̂_c + k·f_tgt,c) / (n_c + k)`，
  收缩目标 `f_tgt,c` 按 §4.3 分层取（本人上层统计 → 人群 → blueprint），`k≈30`。
  **样本少时自动退回上层，不需要 150 手硬门和漂移门**（漂移可以用近 N 手统计代替全历史，跟 `opponent_analysis` 的「近期口径」一致）。
  注意 `ff4302e` 已上线的收缩目标是**人群均值**，不是 blueprint；wopo 人群跟 blueprint 差得多，这里也应该以人群为主。
- 动作类内部（例如 raise 的不同尺寸）保持 σ_ref 的比例，不单独倾斜。
- **抖动不能放在倾斜之前**。原稿写的是 `σ_ε = (1−ε)·σ_ref + ε/|A|`（ε≈0.02）再倾斜，但实测（§4.7）翻前首入节点 92%–95% 的组合
  不在混合区间，牌与牌之间的先后只体现在 1e-4 以下的残余值里；加上 ε/3≈0.0067 后，这些牌全部变成同一个值，
  放宽时多出来的质量就均匀撒到所有弃牌的牌上（ε=0 时 58%–89% 落到次一档的牌，ε=0.02 时只剩 33%–44%，约等于均匀）。
- 兜底平滑 `λ·g` 替代现在的全局 25% 均匀混合，作用是稳健性（范围估错时解不被重度剥削），保留成单独的旋钮。
  `g` 可以先用均匀分布；要保留「对手偶尔拿 AA 平跟」这类可能性又不想灌太多垃圾牌，可以换成按强度排序的分布。
- σ_ref 的排序不能完全交给残余值（理由见 §4.6），第一版给它一个显式的第二排序键：
  σ_ref 低于某个阈值（如 1e-3）的牌，按 Chen 分或对随机牌胜率给一个单调的底值，跟残余值取较大者。

直观理解：**blueprint 决定「哪些牌更可能这样打」（排序），对手的实测频率决定「这样打的牌有多少」（宽度）**。
对手 4bet 率很低 → θ_raise 很负 → 只剩 σ_ref 最偏 4bet 的那几手；平跟率很高 → 平跟范围向下延伸到更弱的牌。

### 4.2 参考策略从哪来

| 情况 | σ_ref |
|---|---|
| 影子同步的决策（锚定前缀） | 该节点 blueprint σ（现状） |
| 断点之后的决策 | 「替身节点」：在 blueprint 里找同位置、同局面类型的节点（例如「面对 HJ 开池的 BTN」代替「面对 HJ 隔离加注、前有一个平跟的 BTN」），查它的 σ。不再整段丢弃 |
| 平跟（blueprint 没有 limp） | 在开池节点上合成三类：raise = σ_bp(raise)，limp 一列用「可玩性」分（例如 blueprint 在同位置面对开池的跟注概率，或 BTN 开池概率）当种子，fold = 其余；再由 rfi 的 raise / limp / fold 实测频率倾斜。得到「会加注的牌之下、能玩的牌」这条带，比「开池范围之外的所有牌」和 Chen 中段都更像真实平跟范围 |
| 短码全下（AllIn tag，现在跳过） | `allin_range_width` 已有的全下宽度表（按 `combos_by_strength` 排序）当 σ_ref，再按对手的全下频率倾斜。hero 决策和翻后搜索从此用同一个全下范围 |

### 4.3 统计口径

局面类直接沿用 `opponent_analysis/spots.py` 的定义，Rust Profiler 照着实现并加对拍测试：

- `rfi` × 位置（raise / limp / fold）
- `vs_open` × 位置组 × 是否有前跟者（fold / call / 3bet）
- `vs_3bet`（fold / call / 4bet）
- `vs_limp`（iso / overlimp / fold；spots.py 还没有，要补）
- BB / SB 的 option（check / raise）

**收缩要分层，不能每格直接收到 blueprint。** 按位置 × 局面 × 是否有前跟者切下来，每格样本很少
（wopo ante200 9B 那一轮总共 93 手）；k=30 时大多数格子很长时间都约等于收缩目标。如果目标直接是 blueprint，
新方法实际就退化成「关画像」，反而不如现在的全局 VPIP / PFR 积累信号快。建议按这个顺序逐层收：

1. 格子实测频率；
2. 本人跨格的整体松紧：例如用该玩家的 VPIP / PFR 解出一个共享的 θ（「这个人整体比 blueprint 松多少」），套到没数据的格子上；
3. 人群（不含本人和 hero，跟 `ff4302e` 的口径一致）；
4. blueprint。

离线库按现在的约定只做先验，可以放在第 2、3 层之间（「该玩家离线频率」）。

格子没有数据时，结果等于上层的统计套在 σ_ref 上。对锚定前缀上的节点，这一步不会出大错；
对断点后的「替身节点」（§4.2）则不然，这时误差全部来自替身选得对不对，§5 的评估要把这类手单独拆出来看。

### 4.4 hero 侧：一个通用重放代替 limp 特例

hero 的翻前决策函数是确定的（给定请求和底牌，输出一个分布）。对每个 hero 过去的翻前步、每个起手牌类（169 类即可，
翻前没有公共牌，只有 limp 规则的 Chen 序和全下胜率有极小的去牌效应），重跑一次 `decide_with` 的翻前部分，
取「实际动作类」的概率当系数。blueprint 路径给 σ（含 PM-17 改过的分布），limp 规则给 0/1，全下启发式给 0/1。

这样 §2.5 的几类偏离一次修掉，`hero_limp_route` / `HeroLimpCoef.nodes` / 前缀里删 hero 步的逻辑都不需要了
（hero 的所有翻前步一律由重放系数表达，前缀里不再放 hero 的决策）。翻前决策很便宜（查表或启发式），
169 × 步数（通常 ≤3）次调用，毫秒级。[推断]

注意：要跟 `decide_with` 共用同一份分流逻辑，不能再写一份，否则又回到「两处必须同步改」的局面
（现在 `hero_limp_route` 就是这样，靠测试 `hero_limp_route_matches_decide` 守着）。
但 `decide_with` 本身不能直接拿来重放：[事实]

- 它返回的是采样后的 `Response`，分布字段四舍五入到 4 位小数（`openpoker_advisor.rs:358`），fallback / 启发式路径根本不填分布；
- 它还带着 `solve_cache` 和 `FourBetTracker` 这类有状态的参数。

所以要先从 `decide_with` 里抽出一个「翻前请求 + 底牌 → 完整动作分布（不采样、不取整）」的纯函数，
`decide_with` 和重放都调它。重放必须用 hero 当时决策用的画像 / PM-17 状态快照，预热路径也一样。
这两份统计在一手结束时才更新（`:5177` `observe_hand`），一手牌内部状态不变，所以取「本手开始时的快照」就够了。
这条要写进约束和测试。

### 4.6 代价与风险

- **排序仍来自 blueprint**。对手的牌序跟均衡差很多时（例如拿同花小连张 3bet、拿 AK 平跟），倾斜只改宽度、改不了顺序。
  这类偏差只有摊牌能看出来，§5 的评估会暴露它；必要时允许按摊牌统计对排序再做一次修正（例如某类牌的额外系数），但不建议第一版就做。
- **边界以下的排序来自残余值，比较脆**。§4.7 显示这些值大多在 1e-4 以下，是 MCCFR 平均策略里早期迭代留下的尾巴：
  量级会随训练次数和平均策略的更新方式变化（9 座 avgfix 重训就是这类问题），换一份 checkpoint 排序可能就变了。
  所以 §4.1 要给它显式的第二排序键。用 regret 或动作价值排序本来更干净，但 crop 只存策略（stratonly），
  要读 15 GB 的 ckpt 才有 regret，实盘机内存扛不住，先不考虑。
- **频率口径错位**：局面分类写错会直接错到范围上。所以统计必须和 `spots.py` 对拍，局面分类函数只写一份。
- **约束用的是本手先验，频率却是历史平均**：`f_c(a)` 是对手在各种先验下混出来的频率，解 θ 时却用本手的 `prior_t`。
  本手先验跟平均先验差得多时（例如前面已经有人 3bet），θ 会偏。v1 可以接受，算已知近似。
- **兜底 λ 不能只按交叉熵调**：λ 的作用之一是稳健性，交叉熵最优不等于 EV 最优；再加上 §5 普通摊牌的偏差，
  按交叉熵调很可能把 λ 调得太小。建议给 λ 设下限（例如不低于 0.05），具体值用 A/B 实盘数据定。
- **改动面大**：建议按 §6 分步，每步都能单独 A/B。

### 4.7 实测：翻前 σ 的渐变程度（2026-10-30）

脚本：`examples/tmp_preflop_sigma_grade.rs`（临时，未提交）。数据：`run_8max_ante100_200bb_antefl2_3bet_cap4_b500` 的 9B crop。
口径：按组合数 × 本座到达概率加权；p = 该动作组的概率（所有加注尺寸和全下合并为 raise）。
「放宽」= 把该动作频率 f 加到 `f + min(15pt, (1−f)/2)`，统计多出来的质量里有多少落到「p<2% 的牌中 Chen 分前 1/3」；
均匀撒约为 33%。ρ = p<2% 的牌里，p 与 Chen 分的 Spearman 秩相关。[实测]

| 局面 | 动作 | f | p∈[2%,98%] | p<1e-4 | ρ | 放宽 ε=0 | 放宽 ε=0.02 |
|---|---|---:|---:|---:|---:|---:|---:|
| UTG 首入 | raise | 21.7% | 5.0% | 73.3% | 0.65 | 81.5% | 33.7% |
| HJ 首入 | raise | 37.6% | 5.1% | 56.1% | 0.68 | 68.1% | 33.8% |
| CO 首入 | raise | 51.0% | 7.2% | 41.6% | 0.52 | 57.8% | 35.0% |
| BB vs UTG 开池 | raise | 7.9% | 17.9% | 65.2% | 0.51 | 88.0% | 39.7% |
| BTN vs CO 开池 | raise | 13.7% | 42.4% | 46.3% | 0.47 | 71.7% | 39.6% |
| SB vs BTN 开池 | raise | 18.8% | 38.6% | 48.6% | 0.55 | 88.5% | 41.8% |
| BTN 开 vs BB 3bet | raise | 5.4% | 21.1% | 47.1% | 0.45 | 69.3% | 43.6% |
| BB 半池 3bet vs BTN 4bet | raise | 12.3% | 35.3% | 42.6% | 0.59 | 89.2% | 42.6% |

结论：

1. 首入节点几乎是纯策略，只有 5%–8% 的组合在混合区间；防守、3bet 节点的混合多一些（18%–64%）。
2. 边界以下的残余值是有排序的（ρ≈0.5–0.7），直接在原始 σ 上倾斜，放宽确实是「往下延伸到次一档的牌」。
3. 倾斜前加 ε/|A| 抖动会把这层排序抹平，退回均匀撒。所以 §4.1 改成「原始 σ 倾斜，兜底放在最后」。
4. call 一栏不能拿 Chen 分当参照：面对 3bet 时，call 的低概率区里装的是要 4bet 的强牌，ρ 本来就是负的
   （「UTG 开 vs BB 3bet」call 的 ρ=−0.71）。完整 29 行里 call 行只作参考。
5. 只看了一份 crop。9 座 flop2 那份没跑；换 checkpoint 后残余值的排序是否稳定，也没验证（见 §4.6）。

## 5. 怎么评估（先做这个）

只用 hh 日志（不用 `/api/hands`），对每个「对手亮牌」的手：

1. 用各方法算该对手进翻牌时的范围 `r`（只用翻前行动）。
2. 记 `−log r(亮出的那手牌)`，以及该牌在 `r` 里的分位。
3. 按方法汇总：平均交叉熵、分位分布是否均匀（校准）。对照组：均匀、blueprint 前缀（不混）、现生产（⑤⑥）、新方法。

**偏差（2026-10-30 修正）**：原稿说「几种方法面对的是同一批手，相对比较仍然有意义」，这个说法不对。
普通摊牌的样本是按牌力筛过的，哪个方法把质量往强牌上推，哪个方法的交叉熵就低。§2.1 / §2.2 那类「把对手想得太强」的错误，
在这把尺子上反而会显得更好。也就是说，偏差会系统性地偏向某一类方法，比较时抵消不掉。[推断]

所以：

- **主指标只用翻前全下的摊牌**。翻前全下以后一定亮牌，在给定翻前行动线时没有经过二次筛选。
- 普通摊牌只作参考；如果要用，得另外建模「这手牌走到摊牌的概率 P(摊牌 | h, 线)」去修正，第一版不做。
- **先数样本量**：在动手写评估工具之前，先从现有 hh 日志里数出翻前全下亮牌的手数，并按对手和局面类拆开。
  太少的话这把尺子本身就不够用，要么等数据，要么换评估办法（例如直接看实盘 A/B 的盈亏），这件事要在 §6 第 2 步之前知道。
- 断点后用「替身节点」（§4.2）的手要单独拆出来统计（§4.3）。

实现上可以放在 `opponent_analysis`（Python，已有重放和摊牌解析）或写一个 Rust example 读 hh 日志调 advisor 的范围函数；
后者能直接测到生产代码，推荐后者。

### 7.1 离线回放：范围长什么样（2026-10-30）[实测]

做法：wopo 三轮 hh（246 手）先全部当 observe 喂进画像（离线先验），再对 hero 看到翻牌的 73 手各发一条翻牌街起点预热请求；
advisor 用 200BB ante-flop2-3bet 9B 的**翻前 crop**（`nlhe_dense_crop --from-crop` 从翻前 + 翻牌 crop 流式再裁，0.46 GiB，
本机 3 GB 内存放得下）+ `--debug-log`，搜索预算压到最小，只看 solve 前打印的根范围（新增 13×13 牌型格）。
开 / 关 `--exploit-limp-tilt` 各跑一遍，44 次脱锚 solve，75 个平跟者范围被倾斜。

- **隔离**：没被倾斜的 102 个座位范围、全部响应来源，两遍逐字相同。
- **人群频率**：未开池时 wopo 人群加注 8%–20%（前位）/ 26%–30%（CO / BTN，前面有人平跟），blueprint 是 25%–38% / 51%–75%；
  平跟 25%–47%。所以 θ_raise ≈ −5 … −11：blueprint 会开池、这些人不加注的牌被推到平跟里。
- **形状**（UTG 首入平跟者，同一手开 / 关对比）：
  - 关（现生产）：72o、83o、52o 这类杂色小牌权重最高，高张和 A 几乎是地板——「开池范围之外的所有牌」，
    这份 blueprint 带 ante 开得很宽（UTG 30%、BTN 75%），所以更偏垃圾牌；BTN 跟着平跟的人只剩 54o–32o 一带。
  - 开：中等高张（J9o、T9o、QJ、KT）、各种 A、小对子、同花连张权重高；AA / KK / QQ / AK 低（留在加注里）；杂色垃圾牌只剩均匀平滑的地板。
- **数据不够的格**：BTN 首入只有 12 条人群样本，加注率被收到接近 blueprint（0.59），平跟范围仍挤在最下面 25%（小杂色连张）。
  这是样本问题，攒数据后会自己变。
- **种子的副作用**：43s、32s 这类小同花连张权重偏高（6–8 / 9），来自 Chen 序给同花、连张加分。对 wopo 不算离谱，但这是种子的选择决定的。

### 7.2 倾斜的两样输入：局面格统计 + 替身节点（2026-10-31）

§0 第 4 条的流水线（每个对手决策 → 参考策略 → 倾斜 → 乘）缺两样输入：除「首入」以外局面的实测频率，和断点之后决策的参考策略节点。
这次只把这两样做出来，**还没接进范围估计**（流水线本身是下一步），生产行为不变：默认配置下逐位相同；
`--exploit-limp-tilt on` 时平跟者的频率会多出第 2 层（见下）。参数都按结构和保守原则给，没有按现有 wopo 数据调。

**局面格统计**（`opponent_profile.rs` `preflop_spots` / `Profiler::spot_freqs`）：

- 局面分类从「首入」扩成五类，每个翻前决策按动作前的局面归格，归不进的（面对 4bet、冷跟 3bet 等）不分类：

  | 局面类 | 条件 | 格 | 动作 |
  |---|---|---|---|
  | `Unopened`（= 原首入） | 没人加注、非大盲 / 补盲者 | 位置组 × 前面有没有人跟 | 加注 / 平跟 / 弃 |
  | `BlindOption` | 没人加注、轮到大盲或补盲者 | 是不是大盲 × 前面跟注 ≥ 2 人 | 加注 / 过牌 |
  | `VsOpen` | 本手第一个动作、面对恰好一次加注 | 位置大类 × 加注后有没有人跟 | 3bet / 跟 / 弃 |
  | `LimpVsRaise` | 没人加注时平跟（或补盲过牌）过，之后第一次面对恰好一次加注 | 位置大类 | 再加注 / 跟 / 弃 |
  | `Vs3bet` | 开池者第一次面对两次加注 | 位置大类 | 4bet / 跟 / 弃 |

  位置大类 = `replay.py` `position_class`（EP / MP / LP / 盲位）。advisor 判本手决策所在的格也调同一个函数；
  advisor 侧的输入改由真栈重放给出（`preflop_real_steps`，按当时合法集判，短码全下只够跟注 = 跟注），平跟者倾斜也换用它。
- **收缩分层**（§4.3 的 1–3 层，原来只有 1、3 层）：人群本格往 blueprint 边际收 10 条伪样本 → 乘上「本人整体松紧」→
  本人本格往它收 `cell_shrink_k`（30）条。「本人整体松紧」= 他在**同一局面类其余格**的实测，相对「人群在这些格、按他每格样本数加权」的期望，
  逐动作类的比值，比值先按 `cell_shrink_k` 往 1 收；只用其余格，本格样本不重复计。哪一层没样本就等于上一层，所以格子切多细不用看数据量定。
  离线库（第 2、3 层之间）没做。
- **对拍**：`spots.py` 补了 `vs_limp`、`blind_option`、`limp_vs_raise` 三类（口径同上表）。wopo 三轮 hh 上，两边都能解析的 230 手共 1910 个决策
  **逐条一致**；差异只有 3 条，都是补盲者在没人加注时加注——`spots.py` 同时记进 `rfi`，这里只记 `BlindOption`（已知差异，`rfi` 原口径不动）。
  另有 8 手 `spots.py` 重放拒收（Rust 侧照常分类）。对拍脚本是临时的，没提交。
- 已知口径差：实盘 driver 只开 `--exploit`（不开 `--exploit-4bet`）时 observe 不带投入金额，短码「全下只够跟注」会被画像记成加注
  （`spots.py` 和 advisor 侧按金额判）。wopo 三轮 2182 个翻前动作里没有一个「`all_in` 但只够跟注」（wopo 这种情况记成 `call`），暂不处理。

**替身节点**（`openpoker_advisor.rs` `spot_substitute`）：从树根按「脚本」走一条规范路径——脚本里的座位按真实动作（加注按池比例映射到最近的抽象档），
其余座一律弃牌——走到替身行动者停下：

| 局面类 | 脚本 | 替身行动者 |
|---|---|---|
| `Unopened` | 空（前面平跟的人当弃牌，同平跟当弃牌映射） | 本座 |
| `BlindOption` | SB 补齐（树里唯一一条「没人加注到大盲」的线；补盲者也用它） | 大盲 |
| `VsOpen` | 开池者加注 + 加注后的跟注者跟注 | 本座 |
| `LimpVsRaise` | 树里没有平跟，用「已投入 1BB、面对这次加注」的盲位代替：加注者不是大盲 → 加注者加注 + 跟注者跟注（大盲自己那一步除外）；加注者是大盲 → SB 补齐、大盲加注 | 大盲 / SB |
| `Vs3bet` | 本座开池 + 开池后跟注者 + 3bet + 3bet 后跟注者 | 本座 |

平跟者（没人加注时跟注过的人，含 SB 补齐）在脚本里一律当弃牌，同平跟当弃牌映射，他们之后的跟注也不进脚本。

提前进翻牌 → 不给节点（这一步仍按无信息处理），不给错节点。

- 测试：影子能同步的线上，每个分了类的决策的替身 = lockstep 实际走到的节点（首入、面对开池有 / 无跟注者、面对 3bet）；平跟后面对隔离加注的替身 =
  lockstep 在大盲那一步的节点；复现不了的线返回空。
